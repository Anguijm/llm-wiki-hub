## Hypothesis

If we classify every automation project into 'get more customers', 'make each customer worth more', or 'cut costs' before building, then scoping and value demonstration become clearer because the metric baseline and success criteria are defined upfront.

## What they did

Nate describes a framing where every AI consulting project must map to one of three business value buckets: (1) get more customers, (2) make each customer worth more, (3) cut costs. He argues that if a build doesn't clearly move one of these needles, it's not worth pursuing because proving value to the client becomes nearly impossible. He gives concrete examples: lead qualification = bucket 1, CRM automation = bucket 2, internal knowledge assistants = bucket 3.

## Relevance to YOLO loop

Provides a pre-build classification step for any agent or automation feature we scope — forces explicit success metrics before writing code, which maps directly to defining acceptance criteria in our dev loop.
