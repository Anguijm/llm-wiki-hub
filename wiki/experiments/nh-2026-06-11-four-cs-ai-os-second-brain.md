## Hypothesis

If we build a Claude Code AI operating system using the four-Cs sequence (static context → live API connections → skills/agents → automated cadence), then productivity will compound over time because each layer enables the next and the system runs autonomously rather than requiring manual triggering for each task.

## What they did

Speaker described his Herk OS v2 AI operating system built in Claude Code using a four-Cs framework. Context: static knowledge files (background, meeting transcripts, 2025 achievements, project docs). Connections: live API integrations (ClickUp, email, QuickBooks P&L, Fireflies transcripts) using scoped API keys with read-only permissions where possible. Capabilities: skills, agents, automations, and pipelines built on top of the knowledge base. Cadence: automations that run on schedule without manual triggering. He defaulted everything through Claude Code (VS Code), maintained a cloud.md file, and used Fable for more complex reasoning tasks. He recommended scoped API keys per integration to enforce a permission layer. The system cost him under $200/month on the max plan with rare limit hits.

## Relevance to YOLO loop

The four-Cs sequence is a concrete build-order for our own agent OS. We can audit our current setup against this framework: do we have static context? live connections? capabilities? automated cadence? Each gap is an experiment.
