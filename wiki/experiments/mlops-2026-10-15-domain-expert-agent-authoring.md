# Let domain experts author their own narrow agents via a no-code harness scaffold

## Hypothesis

If we give domain experts (e.g., nurses, finance analysts) a structured scaffold to define a single narrow task agent without writing code, then adoption and use-case quality will improve because domain experts know the real use cases while builders know what's technically possible—bridging that gap removes the bottleneck.

## What they did

Justin described a recurring failure mode: tech builders don't have the domain use cases, and domain experts don't know what AI can do. He proposed that domain experts need a lightweight authoring path to create their own hyper-scoped agents (e.g., a transcription agent for a nurse), with the standards problem solved so those agents can be shared and composed.

## Relevance to YOLO loop

Maps to the intake/scoping phase of our loop: rather than builders guessing requirements, domain users could self-serve agent creation, reducing spec-translation errors and expanding the agent library without linear engineering effort.
