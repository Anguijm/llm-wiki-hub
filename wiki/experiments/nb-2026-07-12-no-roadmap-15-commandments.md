# Audit every dev-loop process against the 'does it shorten learning loops?' test

## Hypothesis

If we apply a single forcing question—does this meeting/doc/approval shorten the path from evidence to a better product?—to every recurring process in our dev loop, then we will identify and eliminate the human rate-limiters that slow shipping, because humans become the bottleneck when decisions must be re-explained rather than encoded.

## What they did

Nate Jones articulated 15 organizational 'commandments' for AI-era teams, arguing that AI-native companies (Anthropic, OpenAI) ship faster not because of AI itself but because they encode repeatable decisions into durable artifacts (docs, code, evals) so agents can act on them without human re-explanation. The core diagnostic question is: does this process shorten the learning loop? If not, eliminate it. He also warned that partial adoption (e.g. removing roadmaps without getting PMs into the code) produces chaos—the system must be adopted holistically.

## Relevance to YOLO loop

Directly maps to our dev loop: we can run a one-time audit of standups, PR review steps, approval gates, and doc conventions, scoring each against the learning-loop test and flagging anything that is a human re-explanation rather than an encoded artifact.
