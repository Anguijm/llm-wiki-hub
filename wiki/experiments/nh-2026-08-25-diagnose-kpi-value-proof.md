# Identify the constraint first, pick a KPI before building, price on proven value

**Status:** `backlog` · **Effort:** `medium`

## Hypothesis

If we diagnose the actual business constraint before building any automation, select a measurable KPI upfront, and price the engagement based on demonstrated value rather than guessing, then clients will perceive clear ROI and be willing to move to retainer relationships because the value is objectively provable at review time.

## What they did

Nate described three mistakes from an early client engagement: (1) building a personal assistant AI that was not the actual constraint in the client's business, (2) failing to choose a KPI before delivery so there was no way to prove value, and (3) guessing on price rather than anchoring to business impact. He presented a three-step framework: first diagnose the real constraint (like a plumber finding where the pipe is clogged), then pick a single measurable KPI before starting work, then price based on projected value so the client sees a no-brainer ROI. He demonstrated live with an audience member, walking through their funnel to find demand-side constraints, then identifying what to automate (e.g., capturing sales call insights for content). He also described using a 'grill me' prompt to extract subject-matter expertise into the AI system being built.

## Relevance to YOLO loop

Directly applicable to scoping any AI automation project in the dev loop: before writing a single line of code, run the constraint-diagnosis conversation, lock in the KPI metric, and document the value baseline so post-deployment reviews are data-driven rather than subjective.
