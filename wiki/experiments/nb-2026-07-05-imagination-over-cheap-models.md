# Designate frontier-model budget for exploratory 'imagination' tasks

> Back to [[experiments-index]]

**Status:** `backlog` · **Effort:** `medium`

## Hypothesis

If we reserve a portion of AI spend specifically for frontier-model exploratory tasks (questions no backlog contains yet), then we will surface higher-leverage improvements than cheap-model execution alone, because the ceiling on AI value is the size of the list of things you know how to ask for, not the model price.

## What they did

Nate analyzed Mitchell Hashimoto's experiments comparing cheap models vs. frontier models. On standard backlog tasks all models produced equivalent output. But Hashimoto then gave the frontier model a self-directed task—optimizing gnarly systems code he'd written himself—that cost $40 and 2 hours, reached a performance level he couldn't have hit alone, and existed as a task only because an expert suspected something new had become possible. Nate argues this 'imagination layer' is where value has moved as execution commoditizes, and that organizations should give domain experts with context explicit permission and budget to pose expensive frontier-model questions.

## Relevance to YOLO loop

Directly challenges the yolo-loop default of routing everything to the cheapest model. Suggests adding a periodic 'frontier exploration' step where engineers with deep codebase context are explicitly permitted to spend on speculative frontier-model queries to find improvements the task list never captured.
