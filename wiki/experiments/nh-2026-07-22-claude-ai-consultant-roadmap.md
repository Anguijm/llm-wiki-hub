## Hypothesis

If we document a single Claude automation with a concrete before/after time metric and a 2-minute demo video, then we can use it as a replicable template for proving AI value inside organizations because stakeholders respond to quantified time savings over abstract capability claims.

## What they did

Nate outlined a four-step flywheel for becoming an in-house Claude consultant: (1) identify one bottleneck with a measurable metric (e.g., a Friday report taking 4 hours), (2) build the fix using Claude with real process docs and examples, record a before/after demo, (3) prove the metric moved (4 hours → 20 minutes), then present it in a team meeting with the question 'Does anyone have a task they'd want me to look at?', (4) stack wins as case studies to get a retainer or official AI role. He emphasized never pre-populating a rigid memory schema and using Claude as the driver while the consultant owns the business problem framing.

## Relevance to YOLO loop

Directly maps to the YOLO loop's experiment-and-measure cycle: pick one loop step, instrument it with a time metric, automate with Claude, record delta. The demo artifact becomes a reusable prompt+process doc that feeds back into the loop as a verified pattern.
